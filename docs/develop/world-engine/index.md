# 世界模拟引擎设计

## 世界引擎、实体与能力

新增物品的工作量取决于它需要哪些新行为。已有能力的新组合只通过内容注册接入。碰撞、牵引、进食、到期和生成各实现一次，供所有符合条件的实体复用。

| 概念     | 职责                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 世界引擎 | 推进模拟时间，按两种时钟检查到期，调度生成、物理和动作，维护实体索引与关系，并在一次事务中提交变更。                                                           |
| 实体     | 用稳定 ID 表示世界中的一个实例。实体管理自己的行为状态，例如蜘蛛的饥饿值、某颗苹果的进食进度和到期时刻。物理空间持有实例的位姿和速度。                         |
| 能力     | 声明实例可以参与哪些规则。物理读取碰撞形状、质量等参数，牵引检查目标是否可牵引，进食组合目标的可食用能力与行动者的代谢能力，生命周期按实例选择的时钟判断到期。 |
| 内容注册 | 用类型 ID 绑定物理定义、能力参数和外观 ID。生成规则独立注册，场景可为同一物品选用不同规则，也可以直接放置它。                                                  |

蜘蛛是受控实体，提供移动意图和代谢。巢穴是静态实体，提供碰撞形状，其实体 ID 可供归巢和储物规则引用。苹果是一个注册的 `ItemType`。每颗苹果由通用的 `DroppedItem` 工厂创建，用 `itemTypeId` 引用苹果的共享定义。牵引是两个实体 ID 之间的关系，建立或解除它都沿用同一个实例和物理体。

能力可以独立组合。可牵引的物体可以没有食物定义，可食用的物品也可以无法牵引。种群系统按规则的物品 ID 统计实例。不同规则可以复用放置策略和通用物品工厂。动作、物理和快照恢复按能力、形状或注册 ID 工作。界面和 Agent 从已提交的视图读取物品能否牵引和食用，渲染用外观 ID 查模型。

## 游戏里的变化

在 `v2.0` 中，运行时实体统一按 ID 存放。物品挂上蛛丝后继续参与碰撞，松手后从原位继续运动。浏览器以 60 Hz 固定步长推进。本地格式 4 和云端格式 2 保存统一实体索引、控制状态、蛛丝长度、实体 ID 序号与种群计时。石子和浆果已通过物品定义与岛屿规则注册，复用生成、牵引、进食、Three.js 模型构建和存档入口。浆果的有效期按模拟时间推进。下文也描述尚待接入的苹果现实时间到期、营养和觅食。 [物品注册](../../../src/shared/kinds.ts) · [岛屿规则](../../../src/shared/islandContent.ts) · [运行时验收](../../../tests/shared/sim/registeredItems.test.ts)

巢穴和草丛也通过同一注册入口声明能力。注册定义提供局部碰撞盒、足部支撑面、遮蔽体积与视距，以及家的边界和储物网格。世界把局部形状变换到实体位置，碰撞、寻路、感知和存档恢复共用这些定义；移除实体会清理它的所有碰撞盒。初始家的位置在场景放置表中声明，搬离原点后，生成避让、归家判断、地标和储物位置跟随实体。外观构建与贴地处理通过模型注册表接入。景物只按场景注册生成，恢复存档不会补造或迁移景物。

[组合验收](../../../tests/shared/sim/registeredScenery.test.ts)另外注册了一种营地，将家、遮蔽、复合碰撞与足部支撑组合到新类型，并放在原点之外。测试覆盖初始生成、控制移动与石子碰撞、观察、储物、睡眠、恢复及删除。新增已有能力的组合不需要增加系统分支。事务发布仍属于后续重构范围。

蜘蛛移动、物品运动、推挤及物品接触修正现已共用[空间碰撞模块](../../../src/shared/collision.ts)。圆形身体沿完整位移扫掠注册的碰撞盒，在接触点停止向墙内的速度，保留切向运动；圆角按实际圆形边界求交。寻路也用同一连续查询，返回碰撞形状所属的实体 ID。海岸边界和连续高度场沿路径以最多 0.2 米的间隔采样。世界绑定统一提供移动查询、地面、水域和足部支撑，创建与恢复共用该入口。[运行时验收](../../../tests/shared/sim/registeredMotion.test.ts)只注册薄围栏和小弹丸，验证快速运动、推挤、沿墙滑动、寻路和关闭实体碰撞的物品行为。动态物品之间已加入三维球体连续接触：所有物品按同一时间轴推进至最早接触，按注册质量传递冲量，再求解剩余时间。牵引、重力和浮力先汇入速度，之后共用这一过程；已有重叠修正与堆叠支撑也使用相同的接触响应。

[连续接触验收](../../../tests/shared/sim/continuousContacts.test.ts)通过临时注册的不同质量小球，覆盖高速对撞、竖直相撞、连排推挤撞墙、休眠唤醒、牵引传力和非实体穿行。受控身体的完整移动轨迹也交给该物理步；物品被墙阻挡时，引擎裁定身体的实际位置，会话先采纳该位置，再结算动作受阻。受控身体与物品共用实体索引，当前使用竖直柱体检测。接触迭代有预算上限，极端接触堆耗尽预算时保守停止本步剩余运动，避免穿透。

[受控实体模块](../../../src/shared/sim/controller.ts)从内容注册取得速度、转向、升降、碰撞半径和身体净空形状，持有普通实体数据中的控制状态，不依赖 Three.js。世界先推进控制意图和物理接触，提交实际位置后，模型才摆腿和绘制。动作执行器读取控制状态，受控实体被删除或同 ID 对象被替换时结束动作。[受控实体验收](../../../tests/shared/sim/controller.test.ts)临时注册另一种移动能力，验证不增加专用移动或碰撞实现。

模拟会话现在直接创建受控能力，不创建或推进 Three.js 模型。[浏览器呈现器](../../../src/client/rig/presenter.ts)按外观 ID 注册创建骨架，在世界步进完成后读取位置、输入和当前交互目标，再推进摆腿；世界恢复时重新绑定地形与实体，删除受控实体时隐藏骨架。受控模型、肢体求解、材质、地形着色与网格适配均位于 `src/client`。`src/shared` 不依赖 Three.js 或浏览器模块。[无界面验收](../../../tests/shared/sim/headless.test.ts)在 Node 环境禁止导入 Three.js，实际完成创建、移动、牵引、存档、恢复和移除；[呈现验收](../../../tests/client/rigPresenter.test.ts)验证模型变换不会改变物理快照，恢复也不会重置实体速度。

[通用三角网格支撑查询](../../../src/shared/mesh.ts)直接处理普通顶点、法线、索引与位置、旋转、缩放。巢穴石块和根部的定义产生同一份几何数据，世界用它构建支撑查询，浏览器将它适配成 BufferGeometry；引擎启动不需要先构造显示网格。射线对照覆盖所有石块和根部及描边外壳，保证脚落的位置与画面一致。松散物体的滚动四元数同样由纯数学更新，不再加载渲染库。

世界现在独立保存模拟步数、累计模拟秒数与宿主采样的现实时刻。每批浏览器固定步共用同一个现实时刻，观察、感知距离和场景光照读取已提交的世界时钟。动作耗时、物品到期与生成不再借用蜘蛛的动画时间。受控角色被移除后，世界时钟、物品碰撞、到期与种群仍继续推进；物理可以在没有受控体的情况下运行，不再用放在远处的虚拟蜘蛛代替。存档直接保存并校验世界时钟，空闲时间合并到定期保存，隐藏页面时保存准确进度。[时钟验收](../../../tests/shared/sim/worldTime.test.ts)

当前浏览器仍以一个受控角色为镜头和动画中心。多角色模型生命周期、不可变视图与事务事件、代谢，以及按实例选择现实或模拟时钟的生命周期继续按下文推进；当前浆果到期仍使用世界模拟秒数。

[牵引模块](../../../src/shared/sim/tether.ts)已按两端实体关系工作。每条关系保存 `sourceId`、`targetId` 和松弛长度；牵引者注册挂点、容量、初始长度间距、弹性与阻尼，目标独立注册可牵引挂点。物理与绘制共用挂点变换，松散物体之间承受相等反向冲量，受控体与静态体作为运动学端点。世界先累加全部约束冲量，再统一推进碰撞，关系遍历顺序不会改变受力。每个目标最多一条入向关系，各牵引者分别计数，删除任一端会解除相关关系；存档按同一能力规则校验，不推断来源，也不迁移旧的单端记录。

[关系验收](../../../tests/shared/sim/registeredTethers.test.ts)只注册牵引桩、可牵引小车和货物，覆盖两个来源各自的容量、两个动态端点的质量响应、链式牵引、抢占目标的提交时重验、任一端删除以及多来源存档。受控角色的物品列表、可见性和音效只使用自己的关系；其他实体牵着的物品仍在场景中可见。模型挂点与滚动中心共用世界变换，绘制不再把所有绳子连到当前蜘蛛。

本提案把模拟核心、浏览器接入和存档作为一次完整重构来设计。岛屿继续采用连续地形，现有移动、视野、水域、步态、工具调用、本地存档和云同步均纳入验收。苹果改为六口，物理和视觉尺寸按下面的定义缩小。

观察模式采用两个贴地圆环：外圈显示当前视野距离，内圈显示可触及范围。范围只画线，不绘制填充面或逐方向裁剪的多边形。每个物品是否可见、被地形遮挡或被实体遮挡，仍由世界感知查询决定，并通过标记展示。

## 世界内容的方向

本次是完整重构，不承担历史版本兼容。先完成一个可探索、采集、牵引、进食和归巢的 3D 岛屿，保留纸色、描边的视觉风格。现有模型与场景细节可随完整重构重做：统一比例、形体和材质，补充能帮助用户理解世界规则的动作与环境反馈。模型通过外观注册接入，不承载碰撞或物品行为。夜景采用低环境补光与蓝色定向月光，背光面保持暗部；远景与水面淡入深色夜雾，天空保留稀疏星点。避免把整个场景提亮成灰蓝色的白天。黎明与黄昏光源始终保持在地平线上方，白天恢复原有纸色与清晰远景。画面曝光与蜘蛛的感知距离分别处理，昼夜对感知的影响仍由世界规则决定。内容由注册组合形成：树木和石块提供阻挡，草丛提供遮蔽，巢穴提供家与储物空间，苹果与浆果提供不同的食物和生命周期，石子提供不含食物能力的动态物体。

先把昼夜、陆地与水域、物理、生命周期、代谢、动作与生成连成完整循环，再扩充新的生物和资源。新增内容应带来已有规则的互动；需要新能力时先在引擎实现可复用规则，再由内容注册启用。删除旧的迁移、专用物品分支和重复状态，不以保留旧接口为重构约束。

## 状态归属与模块依赖

| 模块       | 负责的状态                                               | 接口                                                                    |
| ---------- | -------------------------------------------------------- | ----------------------------------------------------------------------- |
| 世界       | 地形、时钟、实体身份、实体关系、种群规则和地点标记       | [世界接口](./module_World.ts)                                           |
| 物理空间   | 位置、朝向、速度、接触结果和参与物理求解的牵引约束       | [物理接口](./module_Physics.ts)                                         |
| 运行时实体 | 已吃口数、生命周期阈值、饥饿等实例状态                   | [实体接口](./module_Entity.ts)                                          |
| 内容注册表 | 按稳定的命名空间 ID 查找共享定义和实体工厂               | [内容接口](./module_Content.ts) · [注册表接口](./base.ts)               |
| 动作执行器 | 指令受理、仲裁、动作进度和终态结果                       | [动作接口](./module_Action.ts)                                          |
| 浏览器宿主 | 动画时钟、页面可见性、工具调用的 Promise、写入租约和存档 | [宿主示例](./feature_BrowserHost.ts) · [快照接口](./module_Snapshot.ts) |

世界是公开边界上唯一的写入方。它持有物理写接口，动作执行器通过受限接口交互。实体可以更改自身的行为状态并提出运动意图，物理空间负责提交实际位姿。地形、固定景物、动态物体和受控的蜘蛛共用空间查询。运动、视线和选取可按各自用途筛选查询结果中的形状。

世界只维护一份实体 ID 索引，蛛丝是两个 ID 之间的约束。静态体、动态体和受控体各自决定如何响应力和控制输入，受控体也在同一个空间里查询和碰撞。腿部求解和视觉骨架读取支撑与接触结果，身体变换由物理空间维护。地形生成和渲染继续使用高度场，物理和视线查询从同一份地形与实体定义取得所需的形状。

引擎向界面、Agent 和渲染发布已提交的状态视图与事件。这些调用方通过只读接口获取数据。一次发布内可以共享视图数据，需要独立副本时使用快照。Three.js 对象由浏览器的模型和动画代码管理。

## 一次世界更新的约定

[世界步进示例](./feature_WorldStep.ts)展示一次更新中各模块怎样调用，以及变更何时对外可见。

- 每个固定步推进 **1/60 模拟秒**。浏览器为一批模拟步提供同一个现实时刻。每次动画回调最多运行三步，超出的积累时间丢弃。身体需求和补充计时只随实际执行的模拟步推进。页面隐藏或当前浏览器失去写入租约时暂停模拟，恢复时先按现实时间处理到期，再继续移动。
- 世界先处理到期，再推进种群计时、受理可执行的动作、收集运动意图并求解接触和约束。动作执行器根据已提交的物理结果结算。读取方和存档请求在事务完成后看到同一份结果。
- 每条指令有稳定 ID 和唯一的终态事件。同一行动者最新提交的用户指令在受理时取代之前的动作。自主指令仅在行动者空闲且允许自主行动时执行。处理用户指令期间，包括等待模型响应时，浏览器为用户保留行动者的控制权。取消也通过世界事务结算，并保持两个时钟的原有进度。已取消的指令无法继续吃下一口或更改牵引。
- 移除实体时，同时解除涉及该 ID 的所有关系，并结束引用它的未完成指令。事件和视图一起发布。最后一口吃完时，当前进食指令先成功结束，随后移除实体并让其他引用失效。如果最后一口的结算恰好遇到目标到期，目标先被移除，这一口没有营养收益。
- 页面可见性或租约状态变化时，清空动画计时的积累量。绘制降频时，每次已完成的世界更新仍会交付事件。宿主按指令 ID 找到等待中的工具调用，用同一帧的状态构造工具结果。

## 交互示例与设计决策

### 搬运使用牵引约束

用户拾取够得着的物体时，执行器检查目标仍存在、可牵引且可用。当前蜘蛛注册的容量是七条；其他类型可声明自己的容量。世界根据双方已提交的位姿，从牵引者的挂点到目标建立约束。蛛丝绷紧时产生拉力，松弛时拉力为零。果子保留在空间索引中，继续使用自己的碰撞体。它能撞墙、被拉住抵着墙，或者随牵引者移动绕过墙面。

单纯松手会解除约束，并保留位姿和速度。现有的 `drop` 工具请求把物品放在面前，`store` 请求放到巢内的有效位置。两者都通过相同的碰撞查询校验位置，放置成功后才解除约束。放置受阻时保留蛛丝。工具返回值和音效都根据实际提交的结果生成。 [释放与进食示例](./feature_Interactions.ts)

蛛丝在注册挂点处按弹簧和阻尼计算冲量。两端的松散物体按质量承受相等反向冲量；受控体与静态体保持运动学响应。目标先受到这份冲量、重力和浮力的共同作用，再沿预期位移对地形和实体的碰撞体做扫掠检测。接触时修正速度，使物体的静止与滑动遵守同一套规则。碰撞后的位姿由物理空间提交。受控蜘蛛提供挂点的运动轨迹，自身也在同一空间中求解移动。现有支撑、浮力和松散物体接触计算通过这些接口复用。 [牵引冲量示例](./feature_TetherPhysics.ts) · [现有松散物体求解器](../../../src/shared/sim/physics.ts)

### 苹果、石子和浆果的注册

启动时注册实体工厂、物品定义、放置策略和种群规则，世界创建后各实例共享只读定义。[注册示例](./feature_RegisterContent.ts)为石子和浆果分别增加物品定义和种群规则，并复用同一个干地放置策略。放置策略按候选物理体的形状寻找合适的位置。外观通过各自的模型 ID 注册。

| 物品 | 碰撞体   | 可牵引 | 可食用                   | 到期时钟 |
| ---- | -------- | ------ | ------------------------ | -------- |
| 苹果 | 动态球体 | 是     | 六口，每口提供 10 点营养 | 现实时间 |
| 石子 | 动态球体 | 是     | 否                       | 无       |
| 浆果 | 动态球体 | 否     | 两口，每口提供 4 点营养  | 模拟时间 |

苹果的碰撞体是半径 0.1944 的球体，质量为 0.025，模型缩放系数为 0.54。吃完一颗需要六口，每口半个模拟秒，每完成一口降低 10 点饥饿值。饥饿值从 25 开始，每六个模拟秒增加 1 点，上限 100。达到 60 时，空闲的蜘蛛可以自主觅食。够得着的新鲜食物和蜘蛛已经牵着的食物优先，其次才是走向看得见的果子。触及与视野判断使用 Agent 工具读取的同一份世界视图。执行器把每口所需的时间向上取整到模拟步，在结算时重新验证行动者、目标、新鲜程度和可达性。中断时只保留已完成的口数。

新长出的苹果按设备时间存活 720 秒，最后 90 秒处于腐烂状态。首批苹果的到期时间相隔 24 秒，分散消失。牵引、放置和部分进食均沿用实例自己的到期时间。苹果的岛屿生成规则将地面数量上限设为 20 颗，低于上限时，每累计 24 个模拟秒尝试补一颗。种群系统在达到上限时将该规则的倒计时重置为完整间隔。放置失败也计入一次尝试，重新打开时继续使用原来的生成序列。每次尝试使用的随机序列由种子、规则 ID 和尝试次数共同确定。

### 存档与恢复的边界

世界快照保存实体 ID 分配计数、模拟时间、物理体、实例数据、牵引关系、种群计数和地点标记。浏览器的存档封装负责保存序号、拥有者、租约和待处理指令文本，并沿用现有保存频率。已完成的进食、实体移除和牵引变化会标记待保存状态。空闲时的运动变化仍合并进定期存档。重新打开后可以把保存的待处理指令展示给用户，正在执行的命令和 Promise 由当前会话管理。

本地存档封装采用格式 4，云端采用格式 2，只接收当前格式，不保留旧版本迁移。线上没有需要迁移的用户世界。删除景物修复、旧苹果字段转换、携带物合并和蛛丝长度推断。实体只保存一次：受控角色通过 ID 指向同一个索引，位姿、速度和控制状态都在该实体内；不保存头部和腿部等视觉骨架状态，浏览器根据恢复后的世界重新生成姿态。种群全部按规则 ID 保存，不再有苹果专用计时字段。

恢复保留每个实体的实际高度、速度、朝向和牵引关系；不会重新贴地、重置速度、补齐景物或重算牵引长度。本地写入按序号和时间戳比较，云端继续校验租约与 ETag。未知格式、未知类型、重复 ID、缺失端点或无效控制状态都会拒绝替换当前世界。

先解码并构建候选世界，再替换宿主中的活跃世界、发布状态或写入存档。校验重复 ID、缺失的关系端点、注册类型、数值字段和受控行动者。浏览器具备写入权限时，在发布候选世界的第一份正式状态前，先按现实时间处理到期。采用云端存档时，在同一个 IndexedDB 事务中提交新世界存档和记忆。提交成功后再发布世界并刷新浏览器恢复副本。恢复失败时保留上一次有效的存档和记忆。 [候选世界恢复示例](./feature_Restore.ts) · [现有本地格式](../../../src/shared/sim/snapshot.ts) · [现有云端同步逻辑](../../../src/client/cloud/engine.ts)

## 验收场景

石子和浆果是内容扩展的验收用例。以支持苹果的引擎为基线，只增加这两种物品的定义、外观注册和场景启用的生成规则。碰撞、牵引、觅食、生命周期、生成、渲染和存档恢复都走已有入口。任何额外的系统修改都视为验收失败，包括新增按物品 ID 分支、专用实体工厂或存档格式。

| 场景                                                             | 可观察结果                                                                                                                                                         |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 推滚一颗苹果，牵引它撞墙，再松手                                 | 全程保留同一个实体 ID、碰撞体和速度状态。牵引时仍会被墙阻挡，松手后从原位继续运动。                                                                                |
| 苹果在下一口前腐烂、在最后一口到达结算时点时到期，或在走近时消失 | 按情况返回 `spoiled` 或 `stale-target`。只有之前完成的口数影响饥饿值，视图和事件对实体与蛛丝状态保持一致。                                                         |
| 吃完一颗牵在身后的苹果                                           | 最后一口只结算一次营养，指令只成功一次，苹果和蛛丝在同一份发布结果中消失。                                                                                         |
| 蜘蛛自主觅食期间收到用户指令                                     | 自主指令结束，剩余的自主进食不再结算。用户指令经同一渠道返回结果。                                                                                                 |
| 周一保存，周五打开                                               | 超过现实到期时间的苹果在首次正式发布前被移除，饥饿值和补充倒计时从存档值继续。覆盖地面、被牵引和部分吃过的苹果。                                                   |
| 加载损坏数据或包含未知类型的存档                                 | 旧世界和原存档得到保留，用户收到明确的失败原因。                                                                                                                   |
| 只通过注册加入石子                                               | 按注册的规则生成。能滚动、碰撞和被牵引，进食返回 `not-edible`。牵引中存档并恢复后，实体 ID、物理状态和蛛丝关系延续。                                               |
| 只通过注册加入浆果                                               | 按注册的规则生成。蜘蛛能发现并食用，牵引返回 `not-carryable`。吃一口后存档并恢复，保留已吃口数和到期时刻。仅推进现实时间时浆果留在世界中，模拟时间达到阈值时移除。 |
| 比较现有行为与性能                                               | 用现有测试回归工具、陆地与水中运动、视野和恢复。对照现有帧、寻路与快照基准，并单独测量事件分发。                                                                   |
